Drafting conventions:
- One file per unit, `UA.I.<task>.K<n>.md` for gear 2. A unit can also have `.gear1.md` (Fast-track) and `.gear3.md` (Foundational); without them, the tutor builds those gears from the gear 2 file.
- Header lines `source: <name> | <link>` for every source drawn on. The eCFR section link is the canonical citation for a CFR section. The course keeps the `version:` line and the `draft:` line itself.
- Body: objective, plain-language explanation, a worked example, the common misreading. Gear 3 breaks the point into numbered steps with a memory handle. Gear 1 states the point in one or two sentences.
- No status or review notes in the body.

Gear columns: empty means no file. `drafted` is a file written before versions were kept. `tutor draft v1` is a Foundational lesson the tutor wrote; later students get it, and it waits for an instructor's review. `v3 edited` and `v3 vetted` are saves from the instructor workspace, with the answer to its vetting question. The workspace writes these cells and adds a dated note; edit the table by hand as before for anything else. `v1 drafted` is a file written by hand against the knowledge base, with a version line, not yet vetted.

When to write a gear 3 file: when students keep reaching Foundational on a unit or it gets set aside, or when its tutor draft does not teach the point well. Review the tutor draft first; it is often the quickest start.
