What vetting means

A unit is vetted when a reviewer has checked every factual statement in its lesson files, and every one of its reference facts, against the source text in the knowledge base. The tutor teaches only from these files and keys its questions to the reference facts. A wrong fact teaches a wrong rule with confidence, so the check is sentence by sentence and number by number.

  • Check every number, date, section citation, defined term, and diagram label against the source chunk. Check the arithmetic in the worked example.
  • The CFR outranks the Advisory Circular and the study guide. If two sources disagree, follow the CFR and write the conflict in the Notes column of STATUS.md. Do not smooth it over in the lesson.
  • Review notes go in STATUS.md, never in a lesson file. The tutor reads lesson files verbatim, so a note there reaches a student.
  • A unit is vetted when all its lesson files and its reference facts are vetted. Every unit has a Guided lesson; 8 units also have a Foundational file.
  • The explanation layer of the knowledge base (the .explained.md companion chunks) is a separate, optional check, described in EXPLANATION-LAYER.md.

The README is the instructor guide: how to start the course, how the workspace works, and how to hand your work back. The plan that produced Tasks B to F, with its as-built notes, is content-tasks-b-to-f.md.

How to vet a unit

  1. Pick a unit from the checklist below and read its Notes in STATUS.md. The note names the open question the author left.
  2. Open the lesson. In the workspace: ./start.sh --instructor, click Instructor, pick the unit and the Guided tab. By hand: open the file in an editor.
  3. Open each source named in the file header. The Sources column below links to the knowledge-base chunk and to the official text. Read the source chunk, not its .explained.md companion.
  4. Check each statement in the lesson: who the rule binds, what it requires, every number, date, and section citation, and each defined term. Check that the worked example follows the rule and that its arithmetic is right. Check that the common misreading is in fact wrong under the source.
  5. Check the unit's rows in the reference facts: the fact, the answer, the section, and the link. The answer must say what the section says, in the section's numbers.
  6. If the unit has a Foundational file, check it the same way. A tutor draft is a real lesson file that later students get; your first save removes the draft mark.
  7. Fix what is wrong, in the lesson and in the facts. A fix in the lesson alone is not enough, because questions are keyed to the facts.
  8. Record the result as described next, then run python3 tools/check_integrity.py. Open each link that you added or changed once in your browser.
  9. Click Try it as a student, or start the course, and teach the unit once.

How to record the result

  • In the workspace. Click Save, write a short note on what changed, and answer the question "Is this content vetted against the source text?" Choose Yes, vetted only after every fact, number, and label is checked. The save raises the file's version and writes vN vetted or vN edited into the unit's Gear cell, with a dated note.
  • By hand. Edit the file, then set the unit's Gear 2 cell (or Gear 3) to vN vetted, where N is the version: line in the file. Keep the version line; the course owns it.
  • The facts and the status. The workspace does not edit the Reference facts or Status columns. Write vetted in Reference facts when every row for the unit is checked, and set Status to vetted when all the unit's files and its facts are vetted. Add a dated note.
  • Conflicts. When a source conflicts with the CFR, follow the CFR in the lesson and write the conflict in the Notes column with the sections involved.

After vetting

When you finish your units:

  1. Run the check: python3 tools/check_integrity.py (no --allow-incomplete; every unit has content).
  2. Commit the course material on your branch and open a pull request, as the README describes under "Hand your work back". Do not commit this page.

For the maintainer, after each merge:

  1. Regenerate this page: python3 tools/vetting_guide.py. The summary at the top counts the units whose Status cell says vetted.
  2. Check the links: python3 tools/check_links.py. eCFR answers 429 Too Many Requests after about 30 requests; read the status code before you change a link.
  3. Run the course with a real model from Task A to the practice exam: ./start.sh.
  4. Package: python3 tools/package.py. It refuses a course that fails the integrity check.
